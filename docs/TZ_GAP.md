# Соответствие ТЗ — трассировка требований (Gap Analysis)

Живой документ: сверка реализованного кода с требованиями ТЗ
(`TZ_KidsCard_1.pdf`, версия 1.0 от 26.05.2026).

- **Дата сверки:** 2026-06-04
- **Как читать статусы:** ✅ готово · 🟡 частично / каркас · ❌ нет
- **Приоритеты (MoSCoW):** M = Must (MVP) · S = Should · C = Could · W = Won't now
- **Как обновлять:** при закрытии требования меняем статус и добавляем ссылку на

> grep'ом. Пункты «🟡 каркас» означают, что доменная модель/поток есть, но нет

## Сводка: Must-пробелы, блокирующие «MVP по ТЗ»
По порядку приоритетов ТЗ (раздел 10): сначала безопасность/комплаенс, затем ядро.

1. **AML-мониторинг (правила + алерты)** (FR-KYC-03, UC-17) — 🟡 реализовано в коде (`compliance-service`), ожидает деплоя; санкции/PEP-скрининг и отчётность регулятору ❌.
2. **Аудит-логи** действий над деньгами/данными (7.2) — 🟡 реализовано в коде (append-only + hash-chain), ожидает деплоя.
3. **Реальный KYC** (документ + liveness + провайдер) — 🟡 каркас.
4. **Open Banking с реальным банком** (AIS/PIS, согласия) — 🟡 только мок.
5. **SMS-уведомления** (OTP, критичные события) — ❌.
6. **Локализация uz/ru/en** — 🟡 фундамент + входная зона готовы; дашборд/детские экраны в процессе.
7. **Reconciliation + circuit breaker/retry + Saga** (устойчивость) — 🟡/❌.
8. **Observability** (экспонировать метрики, трейсинг, дашборды) — 🟡.

## Что уже реально работает (сильные стороны)
- Ядро карт: выпуск, несколько карт, блок/разблок/заморозка/закрытие.
- Платежи: **двойная запись (ledger)**, холды, переводы (карта→карта, выплата), диспуты, идемпотентность.
- Лимиты (день/неделя/месяц/категория), мгновенные уведомления (push).
- Геймификация и финграмотность (XP/уровни/стрики/бейджи/уроки), детский интерфейс.
- Семья: родители/со-родители, дети, задачи, накопления, запросы денег.
- Инфраструктура: 7 микросервисов (Kotlin/Spring Boot), Postgres (схема на сервис),
  Redis, Kafka (outbox), Caddy (HTTPS), задеплоено в Узбекистане, **зелёный CI**.

## Рекомендованный порядок (по логике ТЗ)
1. ✅ **Комплаенс-фундамент:** аудит-логи + AML-правила/алерты — реализованы в коде (`compliance-service`), осталось задеплоить + UI комплаенс-офицера.
2. 🟡 **Локализация uz/ru/en:** фундамент + входная зона готовы; осталось мигрировать дашборд и детские экраны.
3. **Устойчивость:** circuit breaker/retry → reconciliation → Saga.
4. **Observability:** метрики/трейсинг/дашборды (видимость для всего выше).
5. **Боевые интеграции:** реальный KYC-провайдер, реальный Open Banking-банк, SMS.
